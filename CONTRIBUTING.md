# Contributing

1. Pick an open issue (the `good first issue` ones are scoped and self-contained) and comment that you're on it.
2. Branch from `main`, keep PRs focused on one change.
3. Build and test locally (see README "Build and run") or rely on CI.
4. Every file has a header comment explaining its role; keep that convention.
5. If you change a design choice, add a row to `DESIGN_DECISIONS.md` with the alternative you rejected and why.
